# 严重等级判定指南

## Critical 🔴 — 直接导致资金损失

触发条件（满足任一即为 Critical）:
- PNL 计算公式错误（符号反转、乘除错误、单位混淆）
- 余额操作非原子性导致丢失或重复记账（double-spend）
- API Key / Secret 明文暴露（日志文件、HTTP 响应、错误消息）
- 未授权交易执行（权限绕过直接下单、无认证接口触发交易）
- 熔断器逻辑错误导致无限亏损（trip 后仍可开仓）
- 止损不执行（设置但从未 enforce）
- 实盘路径与模拟路径行为不一致且影响资金

## High 🟠 — 可能导致资金损失

触发条件（满足任一即为 High）:
- 竞态条件导致重复下单或重复扣款
- 止损/止盈价格计算错误
- 模拟/实盘代码路径混淆（sim 模式意外调用实盘 API）
- 认证绕过或权限提升（viewer 获取 trader 权限）
- WebSocket 数据丢失无补偿机制，导致长时间无信号
- AI 全自动模式下无安全边界（可设置极端参数）
- 余额更新与持仓状态不同步
- 仓位恢复后无风控参数（stop_loss 缺失）

## Medium 🟡 — 影响系统稳定性或数据完整性

触发条件（满足任一即为 Medium）:
- 事件队列溢出丢失信号
- 数据库连接泄漏（未正确关闭）
- 缓存不一致导致错误交易信号
- 异常静默吞没（bare except pass 在关键路径）
- 配置验证不完整（无效值被接受）
- 回测引擎与实盘行为显著不一致
- 内存泄漏（长时间运行后 OOM）
- asyncio Task 未正确取消导致的泄漏

## Low 🟢 — 代码质量或潜在风险

触发条件（满足任一即为 Low）:
- 日志中泄露敏感信息（余额、API key fingerprint 以外的信息）
- 缺少输入验证（非关键路径）
- 硬编码魔法数字（无文档说明的阈值）
- 废弃代码未清理
- 文档与实际行为不一致
- 类型注解缺失或不正确
- 不可达代码（dead code）
- 过度使用 bare except
