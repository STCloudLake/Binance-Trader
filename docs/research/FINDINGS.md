## 1. 摘要（TL;DR）

**一句话结论**：在 1.5 年、8 135 万根 bar 的币安现货缓存上，**六条相互独立的搜索线
（机器学习门控 / 配对协整 / meta-labeling / 遗传算法 / 行情状态条件化与上层编排 / 波动率目标化）
没有任何一条产生出比"直接持有这个篮子"更稳健的样本外优势**；这个平台已经证明的价值是
**测量、风险控制与执行纪律**，而不是 alpha 生成能力；**所有能力都以关闭状态出货**
（`ml.enabled: false`、`risk.vol_targeting.enabled: false`、`risk.liquidity.enabled: false`、
`ga.regime_conditioning: false`、`ai.orchestrator.enabled: false`、P4 四个模块常量全 `False`）。

支撑这句话的三个事实：

1. **每一条线的门槛都是事先写死的**，且每一条线都被自己的门槛拒绝（§2、§4）。
2. **在对齐风险之后，持有篮子赢了**：四个不重叠窗口里，波动率目标化后的持有
   只在**一个**窗口真正胜过原持有（W3，保留 146.4 %），在最优窗口也"只是少持有"，
   而**演化出来的策略在同一批窗口里是 −4.07 % / −2.46 % / −1.59 % / −4.91 %**
   （年化波动率 1.2–2.8 %，基本等于没有参与）——§5。
3. **正收益如果不是来自逐笔优势，就会被如实标出来**：P7-S4 组合体的样本外 +0.4425 %
   背后，717 笔成交的**已实现盈亏合计只有 −3.10 USDT**（§4.5）。

## 2. 方法与可信性纪律

这一节回答一个问题：**凭什么相信上面那句话？** 下面每一条纪律都配一个"如果没有它，
本会话会得出什么假阳性"的具体例子。

### 2.1 门槛事先声明，写进工具源码，先打印后计算

P8 的三个条件（T1/T2/T3）在**任何数字被算出来之前**就以 `THRESHOLD` 常量写在
`tools/p8_beta_harvest_measure.py` 里，并由工具**在打印结果表之前**先打印出来。
P7 的可用性门同样事先写明："样本外组合体成交 ≥ 100 笔 **且** `DSR > 0`"。

> **为什么重要.** 如果门槛是看完数字再定的，那么"我们要的是 Calmar 更好"和"我们要的是
> 回撤更低"之间的选择就变成了结果的一部分。P8 的表里 `V` 臂在**每一个**窗口都把回撤和
> 波动率压下去了；一个事后定的门槛完全可以说"这就是成功"。事先声明的 T1 要求
> **Calmar 在每一个窗口都更好**，而这**不成立**（W0 7.060 < 8.744、W1 3.817 < 10.603），
> 所以结论是 FAIL——见 `P8_BETA_HARVEST_EVIDENCE.md` §6。

### 2.2 只用因果特征；样本内标签**按名拒绝**

`core/strategy/regime_causal.py` 的 `IN_SAMPLE_LABELS = ("calm", "stressed")` 是只有
**整样本 HMM** 才会产出的标签；它们不在门控词表里，一旦被声明就抛具名
`InSampleRegimeLabelError`（在配置加载、基因边界、逐 bar 决策**三处**都拒绝——
"拒绝必须可见"，而不是静默返回 `False`）。整样本 HMM 表另经 `NonCausalRegimeError` 拒绝。

> **为什么重要.** 整样本 HMM 在它自己拟合过的制度上打分，准确率 0.9987；同一结构的
> **因果**解码只有 0.758–0.815（`P7_REGIME_PLAN.md` §0）。把 0.9987 当卖点几乎必然
> 产生"我们找到了状态敏感度"的假阳性。按名拒绝使这条捷径**在代码层不可达**。

### 2.3 去膨胀 Sharpe：试验计数包含试过的每一个变体，并跨运行、跨续跑累计

`core/ga/evolver.py::dsr_trial_counts` + `data/ga_trials.json` 台账：

- 第 g 代被评分的 `N` = **之前已实际执行的**试验数 + 本代 `population`；
- 冠军用同一个函数的 `prior`（不再重复计最后一**代**）；
- per-symbol 模式下 `N = len(symbols) × population × generations`——"臂之间不共享种群，
  但共享搜索的账"（[`06-ga-evolution.md`](../core-algorithms/06-ga-evolution.md) §每币种独立进化）；
- checkpoint 恢复时 `prior_trials` 随检查点恢复，并作为 DSR 的**下限**，不从种群数重启。

> **为什么重要.** 这是本项目**唯一**真正起作用的多重检验防线。P8 把敏感度网格的
> 24 个点全部计为试验，于是 `n_trials = 1 + 24 = 25`；结果是 `DSR(V)` 在四个窗口
> **全为负**（−0.157 / −0.212 / −0.260 / −0.182），而"每期门槛" `E[max] ≈ 0.265`
> 高于任何一期的 `Sharpe`（最好的窗口约 `1.6/√365 ≈ 0.086`）。
> 如果只按"一个事先声明的设置"记 `n_trials = 1`，`deflated_sharpe_ratio` **按定义**
> 返回 0.0（`n_trials ≤ 1` 时不估计），这张表会被读成"没有发现数据挖掘迹象"——
> 完全是反的。工具自己把这条语义写在文档里（`P8_BETA_HARVEST_EVIDENCE.md` §5）。

### 2.4 用**敞口匹配**的基准，而不是满仓 buy-and-hold

`ga.benchmark_mode: exposure_matched`（`core/ga/benchmark.py`，配置里已在册）把篮子
**只在策略自己的持仓区间并集内**持有，权重 `wₛ = clip(mean(amount_usdt)/initial_balance, 0, 1)`
——即策略**实际投入的保证金占比**由成交直接测得。

> **为什么重要，以及本会话的实例.** P7-S1 的直接实测：同一个"几乎每根 bar 都想入场"的
> 策略，在 BTC+ETH / 2025-11-01~2026-01-01 上
> **无过滤 113 笔 / 在场 99.80 % / `exposure_matched` = −0.7973 %**，
> 而 `["trend_up"]` 过滤后 **30 笔 / 在场 27.87 % / −0.7063 %**、
> `["range_low"]` 过滤后 **19 笔 / 在场 23.50 % / −0.0696 %**。
> 两次运行的满仓 `buy_hold_pct` **都是 −21.4446 %**（基准本身没动），而敞口匹配基准
> **随持仓区间变化**——正是把"少交易"和"择时对"分开的那把尺子。
> P7-S4 里这把尺子给出的数更加直白：组合体 +0.4425 %、敞口匹配基准 −0.6917 %、
> 同区间满仓 −11.8160 %，但组合体 717 笔的**已实现 PnL 只有 −3.10 USDT**（§4.5）。

### 2.5 一次性 holdout 窗口会**拒绝**第二次评估

`core/ai/holdout.py`：键 = `(holdout_id, window_start, window_end, timeframe)`，
第二次评估同一窗口默认抛 `HoldoutRefusal`（消息里带上次的 `at` / `fingerprint` /
`revision`），只有显式 `allow_reuse=True` 才继续并把 `reuse=True` 写进产物。

> **为什么重要，以及本会话真实的代价.** P7-S4 的那个窗口被打开了 **3 次**：
> 第 1 次的 enable 份额按 **bar 计数**而非**标签集合**计算，导致所有"≥ 2 个标签"的规则
> 都被算成 100 %，三个随机对照与常开**逐位相同**（`0.5206 / 最大回撤 0.5583 /
> DSR −0.232771`）——那次测量**没有被当作证据**，但它确实看过这个窗口；
> 第 2、3 次是在**看过样本外数字之后**为修 bug 重跑的。
> 该窗口的"新鲜度"因此被消耗掉，`P7_REGIME_EVIDENCE.md` §S4.6 把这一条写成
> "本阶段最该被批评的一点"并留给 Lead 处置（记该窗口为已用，若要一次干净的评估
> 必须换一个从未看过的窗口）。**协议的价值正在于它会痛**。

### 2.6 与干净 `git worktree` 的逐位一致证明

"默认关闭 ⇒ 逐位不变"不是靠 code review 声称的，而是**在独立 worktree 里检出改动前的
版本、用同一个 harness 跑两棵树、按字节比对**：

- `tests/test_ga_benchmark_mode.py::test_buy_hold_is_byte_identical_to_the_head_worktree`
  比对评分值、门结论与旧 provenance 键；
- `tests/test_p7_symbol_mode.py::test_pooled_is_byte_identical_to_the_head_worktree`
  （worktree `d9849a2`），`tests/test_experimental_switches.py`（worktree `3a140cf`）；
- P7-S1 新增字段的证明是**可加性**：整 dump 含 `regime_filter` = `4d40f95abe61d7e2`，
  **去掉该字段后的同一 dump = `809ddf7ba45af011`**（与 P6-D 冻结值逐位相同），
  且该字段的值是 `[]`——加字段必然移动整 dump 哈希，所以证明"新字段是加法的、
  没有动任何旧数字"比钉一个新哈希更强。

### 2.7 独立只读审计

每个阶段都有一次**独立只读审计**，惯例是"不允许称零发现"：
P6 审计判定 **3 MEDIUM + 6 LOW + 3 INFO**（`P6_VOLUME_EVIDENCE.md` §6）；
最终独立审计抓到 F1（实盘波动率缺口闸门**永不触发**）、F3（`t_stat is None` 时
显著性检查**整段跳过**）、F4（`skip_ml_training` 无门控读盘，本仓库 **15 个 `.pkl` /
0 个 `_meta.json`** 全部会被加载）等（`ALGO_UPGRADE_EVIDENCE.md` §8）。
这些缺陷都不是"研究结论错了"，而是"**证据的产出过程不可信**"——
它们决定上面这句话能不能被相信。

### 2.8 DSR 的语义边界（一个容易被读错的点）

`deflated_sharpe_ratio` 在观测 Sharpe ≤ 0 时**定义**为 0（"不估计"），
在 `n_trials ≤ 1` 时也**定义**为 0。因此精确表述是
"**样本外 `dsr > 0` 的单元数 = 0**"，而不是"DSR 估计出负值"。
本文一律使用前一种表述（`P7_REGIME_EVIDENCE.md` §5c 的注、`P8` §5 的注）。

## 4. 六个方向的实测结果

### 4.1 机器学习门控（ML gate）——被自己的门拒绝

特征契约 **v2：54 列**（`feature_schema_hash = 1f30fded996d`；v1 是 39 列 / `335e63360104`）。

| 标的 | OOS AUC | OOS 净成本期望 | 笔数 | t | PSR | 判定 |
|---|---|---|---|---|---|---|
| BTCUSDT 1h | **0.5228** | 0.0000 % | 0 | 0.00 | 0.000 | **拒绝** |
| ETHUSDT 1h | **0.5324** | **−0.4132 %** | 889 | −3.67 | 1.9e-12 | **拒绝** |

独立审计在另一时点复跑：BTC **0.5138** / 净 0.0000 % / t 0.00；ETH **0.5402** /
−0.3089 % / −4.93 —— 同样拒绝（`P6_VOLUME_EVIDENCE.md` §1）。
上游的 P2 测量（v1 契约，39 列）给出同一结论：BTCUSDT 1h P2 门 AUC **0.5207**、
净期望 **−0.2494 %**、t **−4.46**；ETHUSDT 1h AUC **0.5342**、净期望 **−0.1822 %**、
t **−2.28**、PSR **0.011**（`ALGO_UPGRADE_EVIDENCE.md` §2、§3）。

**判定：否证.** 加上 15 个量能/资金流特征之后，方向性门判定**仍未通过**；
`ml.enabled` 保持 `false`，未做任何调参。
门本身是合取式（`t > 2.00` **且** `PSR ≥ 0.95`），且**缺失的统计量一律拒绝**
（`t=None/psr=None` ⇒ `allowed=False`）——这是审计 F3 的修复结果。

**来源**：[`P6_VOLUME_EVIDENCE.md`](../overhaul/P6_VOLUME_EVIDENCE.md) §1；`ALGO_UPGRADE_EVIDENCE.md` §2/§3/§8 F3。

### 4.2 配对 / 协整（Pairs & Cointegration）——0/30

10 个主流币对 × 3 个周期（1h / 4h / 15m）= **30 次** Engle-Granger 检验，
5 % 水平下**通过 0 个**。最好的一个是 BTC/XRP 15m，**p = 0.168**；
4h 上 BTC/XRP **p = 0.171**、ETH/SOL **p = 0.176**——**加密主流币在本样本内不协整**。
窗口间的 β 标准差是 **0.18–0.76**，而数据挖掘基线就是 0.05，即"某些窗口协整"
完全是噪声（[`11-pairs-cointegration.md`](../core-algorithms/11-pairs-cointegration.md)）。

**判定：否证.** 能力的**统计装置**是有效的（模拟 ADF 零分布复现 MacKinnon 渐近临界值；
Engle-Granger 对合成的协整对 **20/20** 在 5 % 水平被拒绝、对独立游走规模正确；
Kalman 动态对冲比跟踪时变 beta），但**真实数据上没找到可交易的配对**。
已知局限：0/30 的样本是 **10 个币对**，不是全市场扫描（缓存里有 496+ 个 USDT 交易对），
这个广度**没有被测过**。

| 指标 | 值 | 门槛 |
|---|---|---|
| AUC | **0.5729** | > 0.55 |
| 净期望（OOS，成本 0.25 %/往返） | **+0.3175 %** | > 0 |

### 4.6 波动率目标化（P8）——四个窗口、三个事先声明的条件、全部失败

四个**不重叠**的 ~92 天窗口，每个窗口前加载 **700 根 1h bar 的估计器暖机**，
所以第一个决策已经看到完整的估计器历史。篮子 = **7 个币**
（ADA, BNB, BTC, ETH, SOL, XRP, ZEC），规则是数据驱动的：
"每个 `1h.parquet` 覆盖整个 2025-04-01 → 2026-10-01 跨度的缓存币种（两端各允许一天）
减去 USD 稳定币对"，排除项与理由由工具打印。

| | 窗口 | 根数 | 再平衡篮子 | 篮子年化波动 | 状态 |
|---|---|---|---|---|---|
| **W0** | 2025-05-01 → 2025-08-01 | 2208 | **+31.01 %** | 53.6 % | 普涨（ETH +105.7 %） |
| **W1** | 2025-10-01 → 2026-01-01 | 2208 | **−1.90 %** | 73.7 % | 崩盘 + 一个离群值（**ZEC +581.8 %**） |
| **W2** | 2026-02-01 → 2026-05-01 | 2136 | **−9.74 %** | 59.9 % | 普跌（除 ZEC 外全跌） |
| **W3** | 2026-06-01 → 2026-09-01 | 2208 | **+12.99 %** | 57.1 % | 混合、高离散 |

**核心发现：`V`（波动率目标化）确实是一个风险降低器，但主要靠"持得更少"。**
回撤在每个窗口都降（22.62 → 15.94、43.47 → 27.60、24.70 → 14.16、27.25 → 17.29），
年化波动率也降（50.8 → 37.6、100.8 → 54.2、69.4 → 43.7、57.8 → 47.2），
但平均总名义曝口只有 **55–87 %**；**换手率上升 5–7 倍**
（**7-10 次/年 → 45-66 次/年**，例如 W0 的 7.87 → 55.61），
于是**成本占毛 PnL 的比例从 0.25-0.98 % 升到 3.5-5.5 %**。

**把曝口差异去掉之后（matched risk，`k = σ_H / σ_arm`，复利）：**

| 窗口 | `V` 保留 `H` 收益的比例 | `DSR(V)`（试验数） |
|---|---|---|
| W0 | **89.2 %** | **−0.1572 (25)** |
| W1 | **57.3 %** | **−0.2115 (25)** |
| W2 | **"少亏"**（`V` −4.88 % vs `H` −10.71 %） | **−0.2603 (25)** |
| W3 | **146.4 %** | **−0.1823 (25)** |

**试验账**：主臂 `V` 是**唯一一个事先声明的设置**（`method="ewma"`、`lam=0.94`、
`window=500`、`target_vol_pct=0.45`、`min_scale=0.25`、`max_scale=2.0`，
直接取自 `config/config.yaml`），但工具同时扫一个敏感度网格：
**4 个估计器 × 3 个目标波动 × 2 个回看窗 = 24 个点 × 4 个窗口 = 96 次模拟**，
因此 **`n_trials = 1 + 24 = 25`**。
在 92 个日观测、25 次试验下，每期门槛 `E[max] = √(1/92)·√(2 ln 25) ≈ 0.265`
高于任何一期的每期 Sharpe（`1.6/√365 ≈ 0.086`）——**即 `V` 最好的窗口也不是
可与数据挖掘区分开的**。

**事先声明的三个条件（工具在打印结果表之前先打印）：**

| | W0 | W1 | W2 | W3 | 合计 |
|---|---|---|---|---|---|
| **T1** `Calmar(V) > Calmar(H)` 每一个窗口 | ✗ (7.060 < 8.744) | ✗ (3.817 < 10.603) | ✓ | ✓ | **FAIL** |
| **T2** 匹配风险下保留 ≥ 80 % 且 "H ≤ 0 时不得亏更多" | ✓ (89.2 %) | ✗ (57.3 %) | ✓ | ✓ (146.4 %) | **FAIL** |
| **T3** `DSR(V) > 0` 在 ≥ 2 个窗口 | ✗ | ✗ | ✗ | ✗ | **FAIL** |

**判定：三个条件全部失败，`risk.vol_targeting.enabled` 保持 `false`。**
（上游简报把 P8 写成"三个预先声明的阈值里有**两个**失败"；以
`tools/p8_beta_harvest_measure.py` 的 `THRESHOLD` 与 `P8_BETA_HARVEST_EVIDENCE.md` §6 为准：
**T1/T2/T3 三个条件各自独立地失败**，T3 只是最严的那一个。这里按文件写。）
额外的诚实说明：网格**没有稳定赢家**（按 Calmar 的最佳设置在四个窗口各不相同：
`realized_cc/0.60/500`、`realized_cc/0.60/500`、`ewma/0.30/250`、
`realized_garman_klass/0.60/500`——这正是被挖掘出的结果的签名）；
而参考臂 `S`（7 个出货冠军）在四个窗口的原始收益是
**−4.07 % / −2.46 % / −1.59 % / −4.91 %，年化波动率只有 1.20–2.82 %**——
**它们基本上一直待在现金里，没有吃到任何 beta**。

**来源**：[`P8_BETA_HARVEST_EVIDENCE.md`](../overhaul/P8_BETA_HARVEST_EVIDENCE.md) §1–§6（全文的数字都由
`tools/p8_beta_harvest_measure.py` 打印并在文档撰写前程序化复核：
240 个指标格 + 24 个匹配风险行、0 处不一致；两次独立全跑在全部 24 个 arm × window
行上**逐位相同**）。

## 5. 结论：本数据上最优的规则就是持有

把 P8 的四个窗口并排放在一起（`H` = 持有篮子；`V` = 波动率目标化后的持有；
`S` = 七个出货冠军的组合，等资本 1/7，参考臂），**唯一诚实的排序方式是"对齐风险之后"**：

| 窗口 | `H` 原始 | `V` 原始 | `V` 匹配风险后保留 `H` 的比例 | `S` 原始（年化波动率） | 人话 |
|---|---|---|---|---|---|
| W0 | **+31.64 %** | +20.92 % | **89.2 %** | **−4.07 %**（1.35 %） | `H` 赢 |
| W1 | **+54.41 %** | +19.88 % | **57.3 %** | **−2.46 %**（1.20 %） | `H` 赢（且被一个 +581.8 % 的离群值主导） |
| W2 | −10.71 % | −1.77 % | **"少亏"** | −1.59 %（2.82 %） | **这一格要小心读，见下** |
| W3 | +11.42 % | +14.16 % | **146.4 %** | **−4.91 %**（1.30 %） | `H` 与 `V` 都赢过 `S`；`V` 这一格赢过 `H` |

**这一格必须小心读（W2）**：`S` 的 −1.59 % 在**原始收益**上比 `H` 的 −10.71 % 好，
但那**不是**一个公平比较，也不是一个可用的结果：`S` 的年化波动率只有 **2.82 %**，
要达到 `H` 的波动率需要 **k = 24.7×** 的杠杆——P8 的工具把 `k > 5×` 的行全部标旗，
并明确写出"对一个几乎全现金的账本放大 85 倍远远超出现金模型的有效范围，
对 `S` 的诚实陈述只能是它的**原始收益**"。也就是说：**`S` 在 W2 少亏，
只是因为它几乎没参与**——它在四个窗口上都是这个状态。

**所以诚实的排序是：**

1. **持有篮子（`H`）**——零参数、零预测、零换手成本。
   W0 +31.64 % / W1 +54.41 % / W2 −10.71 % / W3 +11.42 %（其中 W1 有
   **ZECUSDT +581.8 %** 这个单笔离群值，必须一起读）。
2. **波动率目标化后的持有（`V`）**——**降低了波动率与回撤**（四个窗口全部），
   但在匹配风险后只保留 `H` 的 **89.2 % / 57.3 % / "少亏" / 146.4 %**，
   且换手 45-66 次/年、成本占比 3.5-5.5 %，DSR 四个窗口全负。
   **它没有"击败"持有，它只是"少持有一点"。**
3. **演化/条件化/编排出来的策略**——七个出货冠军在四个窗口上的原始收益是
   **−4.07 % / −2.46 % / −1.59 % / −4.91 %，年化波动率 1.2–2.8 %**
   （P8 §表 3 的 `S` 行）。**它们没有参与**：几乎全现金，既没吃到 beta，也没拿到 alpha。

**把这句话说白：**

- 在这个数据、这个时期、这个品种集合上，**没有任何一条被测量的搜索线找到了
  稳健的短周期优势**；六条线各自的失败模式都被记录在案（多重检验噪声、
  曝口效应、状态不稳定性、门槛不可达、单笔离群值主导）。
- **这个平台已经证明的价值是测量、风险控制与执行纪律**：
  事先声明的门槛、因果特征、诚实的试验计数、敞口匹配基准、一次性 holdout、
  逐位一致证明、独立只读审计——**以及把"看起来很好"的候选（fitness 41.82 /
  Sharpe 9.01 / 382 笔 / 回撤 0.11 %）拒绝掉**的能力。
- **不要**把 `+0.4425 %` 这类组合体数字读成"策略有每笔优势"（其身后是 −3.10 USDT
  的已实现 PnL），也不要对 `ml.enabled`、`risk.vol_targeting.enabled`、
  `ga.regime_conditioning`、`ai.orchestrator.enabled` 抱着"打开就有用"的期待。

## 6. 我们自己证据的局限

这一节存在的理由是：**一个不被限定范围的结论就是一句口号。**

1. **只有现货、只有一家交易所、只有 OHLCV。** 没有资金费率 / 基差 / 未平仓合约，
   没有逐笔与订单簿数据，没有期权数据。
2. **只有约 1.5 年**（2025-04-01 → 2026-10-01），**品种只有一小把**
   （全跨度 48 个文件覆盖 8 个币）。
3. **样本外窗口太少（P7-S4 只有一个）**，而且其中一个窗口（P8 的 W1）
   **被单一品种主导**：`ZECUSDT +581.8 %`，其余六个币亏 14.6–58.7 %。
   用四分之一窗口的一个离群值驱动一个结论是**本缓存的真实特征，不是市场规律**。
4. **P8 的策略臂不得不在 1h 上跑**，因为引擎评估一个策略**声明的最短周期**
   （`core/backtest/engine.py:534` 的 `min(strategy.timeframes, key=_tf_minutes)`），
   而四个出货冠军声明了 `1m`/`5m`——原生多月的回测是**小时级**而不是分钟级。
   这**降低**了这些策略相对于它们被演化时的表现，所以 `S` 只是参考臂，
   **从来不是标尺**。
5. **meta-labeling 的证据建立在"重扫窗口/币种"之上，而不是一个独立数据集**：
   88 个候选是从**同一段缓存**里切出来的重叠窗口，它们不是互相独立的信息。
6. **P8 的匹配风险重标定是对同一条交易规则的曝口重标定，不是重新模拟**：
   它没有重新定价被缩放后的账本的交易成本，且在 `k > 5×` 以上离开了现金模型的有效范围
   ——所以 `S` 的匹配风险行被标了旗，对 `S` 的诚实陈述只能是它的**原始收益**。
7. **配对只测了 10 个币对**，不是全市场（缓存里有 496+ 个 USDT 交易对）。
8. **门槛本身可能太严，我们如实报告而不放宽**：以约 92 个日观测，
   P8 的去膨胀门槛高于该族所有 Sharpe，所以 T3 本来就会失败——
   但 T1 与 T2 **独立地**也失败了，所以判决不依赖这一点。
9. **`garch11` 没有进 P8 的网格**：实测 0.125 s/次调用 × 600 根 × 9 个 symbol-window
   ≈ **11.3 分钟**只为预测，超出有界预算。这是**预算决定并已被测量**，
   不是对它质量的判断。

## 7. 什么会改变这个结论

下面这些是**具体**的、会让我们有理由重新评估的事情（不是"再多做点研究"）：

1. **非方向性的收益来源：资金费率 / 基差 carry（funding-rate / basis carry）
   以及其他非方向性溢价。**
   ⚠️ **本会话没有验证资金费率数据的可达性**——我不知道这个环境下能否取到
   历史资金费率或基差数据，这是一个**未验证的前提**，必须先验证再谈结论。
   这类收益不依赖预测方向，与本项目"方向不可预测"的实测结论**不冲突**，
   但它需要**合约数据**与相应的执行/风控/保证金语义，而那是一套新的工程。
2. **更宽的品种集合做相对价值（relative value）。**
   0/30 的配对结论只覆盖 10 个币对；如果要在 500+ 个 USDT 交易对上扫描，
   必须先建立**多重检验的试验记账**，否则结果一定是噪声。
3. **逐笔（tick）/ 订单簿数据。** 本项目所有的微观结构特征都已经实现并被证明因果、
   有硬上限与 TTL 缓存，但**盘口深度从未被用来建模**（`impact_k` 是
   ILLUSTRATIVE, NOT CALIBRATED 的示意值）。
4. **其他交易所或资产类别**（跨所价差、股票/ETF/商品）。
5. **更长的历史**（把 1.5 年扩到多个市场周期，尤其是包含多个"离群值窗口"的样本）。
6. **一个从未被打开过的、真正干净的一次性 holdout 窗口**——P7-S4 的那个已经被
   三次访问消耗掉了（§2.5）。

## 8. 工程缺陷与修复（研究纪律的副产品）

**研究纪律的直接副产品是它顺手抓出了真缺陷。** 每一条一行，全部有 before/after 实测：

1. **静默不可求值的 `sma` 条件**（`b59af1d`）：`compute_all` 的"总是派生"块补齐了
   volume_sma/volume_ratio/ema_fast/ema_slow 却**漏了 `sma`**，而基因声明其总是可用、
   清洗器兜底正会生成 `close > sma`/`close < sma` → 求值器报 `unknown column` 并返回
   全 False 掩码，条件被**静默丢弃**（线上日志恰 6 次、全为 sma）。
   修法：补 `SMA(close,20)`（实测 9000 根上 1.323 → 1.404 ms/调用），
   并把含不可求值条件的基因组改为**显式失败**（`UnevaluableConditionError`、
   fitness −999 + flag + 计数 + 每基因组一条警告，结构性排除出选择）。
2. **GA 进度不可见**（`9d6f423`）：根因是多进程评估**只在"整块（7–8 个基因组）算完"时
   上报一次**（该任务一块需数小时），于是"一个跑了 25 分钟的任务"与"一个卡死的任务"
   在面板上完全一样。修法：转发引擎已有的逐 bar 观察器 + 每完成一个基因组发一次 tick，
   并把载荷扩为 `phase/generation/total_generations/eval_completed/eval_total/
   eval_equivalent/chunk_progress_pct/bar_step/bar_total/elapsed_s/best_fitness/
   best_trades`；新增只读 `scripts/ga_job_status.py`（对修前任务也可用，
   **进度过期即非零退出**）。
   > 刻意**不**把块拆成逐基因组：`max_positions = max_open_trades // 策略数` 会让
   > 单基因组拿到 15 个槽位而不是 1，**改变 GA 结果**——可观测性不能改变被观测的东西。
3. **续跑把种群重新编号并多跑代数**（`9f86e63`）：原实现**覆盖代数、从 1 重新编号、
   再跑满 `cfg.generations` 代**。修法：resume 从 checkpoint 记下的代数继续并在任务的
   `generations` 处停止；试次计数（prior/this_run）随 checkpoint 恢复并作为 DSR 的
   **下限**（不重复计、不从种群数重启）。
4. **静默覆盖 window 不同的 checkpoint**（`9f86e63`）：改为**具名错误**拒绝，
   walk-forward 降级为下一窗口重新开始——"覆盖"会让两个不同窗口的搜索账混在一起。
5. **单染色体路径把 `alpha_vs_benchmark_pct` 覆盖为 0.0**（`f7cd14b`）：
   `evaluate_chromosome` 曾把**原始 stats** 传给 `benchmark_result_fields`，
   使单染色体路径把该字段写成 `0.0`——实测该窗口 **0.0 → −1.8063**，
   修后与批量路径一致。（既有 2 个冠军 YAML **保留历史错误值未重写**，
   这也是为什么读旧 YAML 时要小心。实测残留：`ga_champion_1790855974.yaml` 与
   `ga_champion_1790867208.yaml` 的训练记录分别是 `1.8152` 与 `2.0372`，
   而它们的 **`provenance.validation` 块都写着 `alpha_vs_benchmark_pct: 0.0`**——
   这些是修复前写下的历史值，本文的任何结论都不依赖它们。）
6. **一条测试钉的是"依赖数据的结果"，而不是门的契约**（`bf2c055`）：
   `tests/test_meta_labeling.py::test_real_primary_rules_are_refused_by_the_meta_gate`
   原先断言 `gate["allowed"] is False`；换缓存后这个断言过期
   （`bb_breakout`/BTCUSDT 现在**真的**过门）。改为断言**门的语义**：
   `allowed ⇔ 由载荷自身数值与阈值推导出的每条判据成立`，
   拒绝必须点名失败判据并引用那些数字，**当前缓存上的判定是被"记录"而不是被"钉住"**。

**来源**：`ALGO_UPGRADE_EVIDENCE.md` §6（`637e655`）、§8（F1/F3/F4/F5.2/F5.3、`bf2c055`、
`b59af1d`、`9d6f423`、`9f86e63`、`f7cd14b`）；`tests/test_meta_labeling.py:401-428`（docstring）。

## 9. 如何复用这套方法论（给别人的清单）

把下面这九条当成"给自己的假设上刑"的清单。**它们不提高收益，它们提高你被自己骗到的成本。**

1. **先写门槛，再写代码。** 把验收条件做成源码里的常量，并让工具**在打印任何结果之前**
   先打印它。事后调整门槛，等于把结果的一部分写进了判据。
2. **用因果特征，并对样本内标签"按名拒绝"。** 不要让"只能整样本算出"的量有任何
   到达决策点的路径——包括不要让它静默返回 `False`（拒绝必须可见）。
3. **把试过的每一个变体都记进试验账，跨运行、跨续跑。** 网格扫描的每一个点都是
   一次试验；`n_trials = 1` 会让去膨胀 Sharpe **按定义**返回 0，从而把"没检查"
   误读成"没发现数据挖掘"。
4. **用敞口匹配的基准，而不是满仓 buy-and-hold。** 一个只在一小部分时间持仓的策略，
   跟一个 100 % 在场的基准比总收益，惩罚的是"拿着现金"，不是"选错"。
   把"少交易"和"择时对"分开，是这套方法里最便宜、收益最大的一步。
5. **让 holdout 窗口能拒绝你。** 加一个计数器，第二次评估同一窗口就抛异常；
   要看第二次必须显式 `allow_reuse=True` 并把 `reuse=True` 写进产物——
   **让代价可见**。
6. **用干净 worktree 做逐位一致证明。** "默认关闭 ⇒ 行为不变"应该在**独立的
   `git worktree`** 里检出改动前的版本、用同一个 harness 跑两棵树、按字节比对。
   新增字段的更强证明是**可加性**（去掉新字段后与冻结值逐位相同）。
7. **写一条"必须拒绝"的合成对照。** 每个门都要有一个确定性的、一定要被拒的输入，
   否则你无法区分"门在工作"和"门恰好没有拒绝"。
8. **让独立只读审计有权力说"不能称零发现"。** 审计要能改的是**证据的产生过程**，
   而不是结论；它的产出应该是可复现的命令与 before/after 数字。
9. **把"正收益从哪里来"写成必答题。** 每一个正收益都要能回答：是逐笔优势、
   是曝口路径、还是基准选择？如果答案不是逐笔优势，就**不要**把它写成"策略有效"。
